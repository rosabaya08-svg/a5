# PayUp 장바구니 차액정산 내부 완료 보고서

- 기준일: 2026-07-30 KST
- 대상: A5S PayUp 장바구니 차액정산, 중앙 PayUp 제어센터, 배포 및 운영 안전장치
- 외부 인증키 원문과 계좌·연락처 원문은 이 문서에 기록하지 않는다.

## 1. 내부 구현 완료

- PayUp v1.2.0의 하위가맹점 등록·수정/조회, 승인내역 조회, 정산목록/상세 응답 계약을 필수 필드 단위로 검증한다.
- `subMerchantId`는 영문·숫자 1~20자, 사업자번호는 숫자 10자리로 제한한다.
- 조회기간은 실제 달력 날짜이면서 시작일과 종료일을 포함해 최대 31일로 제한한다.
- 성공 응답의 `merchantId`, `listCount`, `list`를 검증하고 요청 MID 및 실제 행 수와 일치하지 않으면 저장하지 않는다.
- 승인 호출 전 트랜잭션 잠금을 획득하고 중복 호출, 진행 중 호출, 결과 미확정 거래의 재호출을 차단한다.
- 승인 응답은 주문번호·금액·거래번호가 모두 일치할 때만 결제 완료로 인정한다.
- 네트워크 단절 등으로 승인 결과를 알 수 없는 거래는 `reconciliation_required`로 보류한다.
- 승인내역 조회에서 주문번호·금액·수취인별 ID·사업자번호 해시·분배금액이 모두 일치하면 결과 미확정 거래를 자동 복구하고 주문·재고·공급사 원장을 확정한다.
- 수취인 누락, 추가, 중복, 금액 불일치 또는 정산 상세 불일치는 지급 보류와 수동조치 큐로 전환한다.
- 정산 요약과 상세의 건수·총액·수수료·부가세·공급액을 상호 대사한다.
- 인증번호·카드번호·계좌번호·연락처는 마스킹하며 원문 승인 응답은 저장하지 않는다.
- 하위가맹점 등록은 테스트 환경에서만 결정적 ID 생성을 허용하고 운영 환경은 PayUp이 확인한 명시적 ID를 요구한다.
- 테스트 MID/키는 운영 Secret과 분리된 테스트 전용 Secret에만 저장한다.
- 직접 PayUp 취소는 기본 비활성화하고 판매사 직접취소 요청 및 지급 보류를 기본 정책으로 적용한다.

## 3. 배포 및 권한

- `a5s-mall`의 PayUp 관련 함수 18개를 Node.js 22 2세대 함수로 선별 배포했다.
- 배포 후 결제, 하위가맹점, 대사, 취소, 테스트센터 함수가 모두 `ACTIVE`임을 확인했다.
- 운영 직접취소 환경값은 `false`로 반영됐다.
- 중앙 PayUp 함수 서비스 계정에는 `a5s-mall`의 `roles/datastore.viewer`만 부여했다. 쓰기 역할은 추가하지 않았다.
- Cloudflare Pages 출력 폴더를 실제 Next.js 정적 산출물인 `out`으로 수정했다.
- Cloudflare Pages 운영 브랜치를 오래된 기능 브랜치에서 `main`으로 수정했다.

## 4. 현재 하위가맹점 상태

| 업체 | 테스트 내부 상태 | 운영 내부 상태 |
|---|---|---|
| (주)해성청과 | `granted`, 결제 허용 | `invalid_provider_registration`, 결제 차단 |
| 위드커머스 | `granted`, 결제 허용 | `pending_payup_live_verification`, 결제 차단 |

테스트 내부 상태는 A5S 제어문서 상태이며 PayUp 서버 등록 성공을 의미하지 않는다. PayUp 조회 인증이 성공한 뒤 `/list` 결과로 다시 검증해야 한다.

## 5. 외부 차단 상태

테스트 전용 Secret에 저장된 자격증명으로 다음 읽기 전용 API를 다시 호출했다.

- 하위가맹점 목록
- 승인내역 목록
- 정산 목록
- 정산 상세

네 API 모두 HTTP 200 JSON 응답을 반환했지만 PayUp 응답코드는 `7001`이었다. 따라서 하위가맹점 `/update`, 결제 승인, 취소 호출은 수행하지 않았다.

PayUp 개발팀이 테스트 MID와 장바구니 API 인증키의 매핑·권한을 수정해 네 조회 API가 `0000`을 반환하기 전까지 외부 연동과 실제 결제 판정은 `NO-GO`다.

## 6. 외부 해제 후 실행 순서

1. 네 읽기 전용 조회 API가 모두 `0000`인지 확인한다.
2. 테스트 `/list`에서 두 하위가맹점의 정확한 ID와 사업자번호를 확인한다.
3. 누락된 테스트 하위가맹점만 `/update`하고 즉시 `/list`로 재검증한다.
4. 1,004원 단독 두 건, 2,008원 복수 분배, 실제 상품·배송비 포함 결제를 순서대로 승인한다.
5. 승인내역의 총액과 수취인별 분배금액을 내부 원장과 대사한다.
6. 판매사 직접취소 처리 후 취소내역과 정산 복원을 대사한다.
7. 운영 MID, 운영 하위가맹점 ID, 고정 IP 허용이 확인된 뒤에만 운영 플래그를 연다.
